# Data schema

All game data lives in **modules**: JSON documents under `data/modules/`, one
directory per module type, one file per instance. `docs/DATA_MODEL.md` lists the
module types, their fields and how a Scenario ties them together; this page
covers the parts whose meaning isn't obvious from the fields. Everything under
`derived/` and `exports/` is regenerated by the scripts in `tools/` — never
hand-edit those two directories. Humans edit `sheets/*.ods` and import them
(`docs/PIPELINE.md`).

## Map: locations

Every location (land territory or sea zone) has an integer `id` unique across
land and sea, a `name`, a `type` (`land`/`sea`), and an anchor point `x`/`y` in
the map image's pixels — the point the boundary extraction floods from, and the
label position for tools. `area_px`, `bbox_w`, `bbox_h`, `boundary` and
`adjacency` are generated. GC72: 144 locations, 82 land and 62 sea.

Owners, values and Strategic Centers are not on the map: they are the
FactionAssignment, MapValues and SCAssignment modules, so one map can carry
several allocations.

## Map: adjacency

Two locations are adjacent when their real outlines (`boundary`) touch — within
a few pixels; a sea zone counts as its visible water only, since its polygon
also covers the coast it borders. Regenerated by `tools/compute_adjacency.py`
(see `tools/outline_adjacency.py`); nothing in it is hand-edited. On a
`cylinder` map the touch test wraps east-west (x = width is the same seam as
x = 0; north-south never wraps). Two land spaces separated by water are not
adjacent — they connect through the sea zone between.

`adjacency_overrides` holds the hand-confirmed corrections applied on top:
`remove` pairs that touch but aren't adjacent in play (mostly a sea zone whose
polygon merely overlaps a coast it doesn't border), `add` pairs that are
adjacent in play but don't touch. Each is `[id, id, "names"]`; only the ids are
read. The compute step warns about an override that no longer has an effect.

Each location's `adjacency` list is sorted by id; its order carries no meaning.

## Map: boundaries

Vector outlines for every location, extracted from the map image by
`tools/extract_territory_shapes.py` (which shares classification logic with
`tools/render_map.py` through `tools/map_geometry.py`). Each location has a
LIST of polygons — usually one; island-chain territories (Cuba, Falkland
Islands, Philippines, New Guinea, Hawaii, Polynesia) and a couple of sea zones
with border-art gaps have several — each a list of `[x, y]` vertices, closed
(no repeated last point), simplified to `boundary_epsilon_px`. A sea zone's
polygon is its outer boundary only: islands it encloses are NOT cut out, so
consumers must draw land after (on top of) sea. Coordinates are in the flat
image; stitching across the east-west seam is a rendering concern.

A handful of sea zones (Labrador Sea/Gulf of Mexico, Eastern/South-Eastern
Indian Ocean) share a connected water region with no drawn border in the
source art; those are split by nearest anchor point (a local Voronoi split —
see `map_geometry.sea_territory_masks`), so the boundary there is a straight
line.

## FactionAssignment: sea deployment

A coastal land location's `sea_deployment_location_id` is the sea zone its
naval units (and the aircraft on their carriers) start in when a starting setup
is generated. GC72's are the nearest adjacent sea zone to the anchor point,
chosen so that no two factions share a zone. It only feeds setup generation;
in play, naval purchases follow the rule set's purchase rules.

## InitialSetup: units

Units are listed where they start. `purchased_at` is set when a unit was bought
at a different location (a ship or carrier aircraft bought at a coastal
territory); the setup validator counts it against that territory's stacking
cap. An air unit starting at sea is on its faction's carrier there. A faction's
units are placed in unit-id order (natural sort: `NAA-2` before `NAA-10`),
which fixes each unit's in-game `unit_id`; UnitPromotions names units by these
setup ids.

## derived/adjacency_foreign.json (regenerated)

For every land territory: its land-neighbour ids (`adj`), and the subset
belonging to a different faction (`foreign`). Built by
`tools/compute_foreign_neighbors.py`.

## derived/faction_territory_profile.json (regenerated)

For each faction, its owned land territories with the fields the setup tools
need: stacking cap (value + 3, + the SC bonus at a Strategic Center), coastal
flag, sea deployment zone, and whether it has a foreign neighbour. Built by
`tools/compute_faction_profile.py`.

## exports/

`map.png` (the rendered faction map) and the adjacency/shape preview images —
pure build products, see `docs/PIPELINE.md`.
